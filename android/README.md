# Bloom для Android

Нативный клиент на Kotlin и Jetpack Compose. Светлая тема повторяет направление референса: молочный фон, розово-сиреневые акценты, мягкие карточки и четырёхлепестковый знак Bloom. Тёмная тема включается на приветственном экране или в профиле. Выбор сохраняется. Лепестки пульсируют при загрузке.

Посмотреть оформление: [светлая тема](design/bloom-light.png), [тёмная тема](design/bloom-dark.png). Это отрисовка приветственного экрана из Compose-компонентов через Robolectric; снимки с физического телефона пока не сделаны.

## Что подключено

| Сервис | Сценарии приложения |
| --- | --- |
| Identity, Java | Регистрация и вход по телефону **и паролю**, обновление access token, выход |
| Users, Java | Создание/редактирование анкеты, каталог интересов, приватность, ссылка на профиль, блокировка, удаление аккаунта |
| Interactions, Java | Лайк, пропуск, особый интерес, взаимное совпадение, список совпадений с пагинацией, отмена совпадения |
| Chat, Go | Список комнат, создание комнаты с собеседником, история и сообщения по WebSocket |
| Discovery, Go | Подготовлен адаптер `/discovery/feed`; пока сервис не реализован, показывается состояние недоступности |
| Media, Go | Загрузка и просмотр вложений **не включены**: сервер пока отдаёт файлы без проверки доступа. Подробности в [integration.md](integration.md) |

Приложение обращается **только к API Gateway**. Ему не нужны адреса отдельных сервисов, Kafka, пароль базы или `X-Internal-Token`. Вход возвращает пользовательские токены; клиент сам добавляет `Authorization: Bearer …` к запросам. Refresh выполняется один раз для параллельных ответов 401. Токены зашифрованы AES-GCM ключом Android Keystore; резервное копирование приложения отключено.

Это первый рабочий клиент, а не готовый релиз магазина. Нет SMS-входа, push-уведомлений, фонового чата, карты, звонков, событий и приватных вложений: соответствующие серверные сценарии ещё не готовы. Фото профилей пока заменены фирменной карточкой с инициалом. В приложении нет подставных пользователей или сообщений.

## Быстрый запуск на своём телефоне

1. На компьютере с Docker обновить конфигурацию **из корня Bloom**:

   ```powershell
   .\setup.ps1
   docker compose -f compose.yml -f .local/compose.yml up -d --build
   ```

   Скрипт дополняет существующие настройки без смены паролей. Chat и Media получают служебный токен Identity через `.local/compose.yml`; в APK он не попадает.

2. Установить debug APK: `android/app/build/outputs/apk/debug/app-debug.apk`. Android 8.0 или новее. Для ручной установки разрешить установку из используемого файлового менеджера.
3. Телефон и компьютер подключить к одной сети. Проверить в браузере телефона `http://IP_КОМПЬЮТЕРА:8080/docs/`. Если страница недоступна, проверить публикацию порта Gateway и правило Windows Firewall для частной сети.
4. На приветственном экране Bloom нажать **шестерёнку**, указать:

   ```text
   http://192.168.1.50:8080/api/v1/
   ```

   Заменить IP на адрес компьютера с Docker. `localhost` на телефоне означает сам телефон. Адрес эмулятора Android Studio по умолчанию — `http://10.0.2.2:8080/api/v1/`.
5. Создать аккаунт с номером в международном формате и паролем от 12 символов. Заполнить анкету. Никакого кода SMS текущий Identity не отправляет.

Если телефон подключён к этому же компьютеру по USB с включённой отладкой, можно использовать:

```powershell
adb reverse tcp:8080 tcp:8080
```

Тогда адрес в приложении — `http://127.0.0.1:8080/api/v1/`. Здесь Docker должен работать на том же компьютере, к которому подключён телефон.

## Как проверить знакомство и чат вдвоём

1. Два аккаунта создают анкеты на одном сервере.
2. В «Профиль» нажать кнопку «Поделиться анкетой». Получится `bloom://profile/UUID`.
3. Второй человек вставляет ссылку в поле на экране «Для тебя» и открывает анкету. Ссылка также открывается Android напрямую, если приложение установлено.
4. Оба ставят друг другу лайк. В «Совпадения» появится человек.
5. Нажать «Сказать привет». Go создаст/откроет комнату. Переписка использует настоящий WebSocket Gateway.
6. Сообщение появляется после ответа сервера. Если подтверждение не пришло за 15 секунд, текст возвращается в поле; перед повтором нужно проверить историю. Автоматического повторного POST/отправки сообщения нет.

Пока Go не обрабатывает события отмены совпадения/блокировки, эти действия **не гарантируют закрытие существующего Go-чата**. Это серверная задача, перечисленная в integration.md.

## Разработка и сборка

Открыть **папку `android` отдельно в Android Studio**. Серверный Gradle-проект остаётся в `server`; Java- и Go-разработчики работают независимо от клиента.

Нужны JDK 21 (подходит bundled JBR Android Studio), Android SDK Platform 36 и Build Tools 36.0.0. SDK настраивается Android Studio или через игнорируемый `local.properties`:

```properties
sdk.dir=C\:/Users/USERNAME/AppData/Local/Android/Sdk
```

В PowerShell из `android`:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Linux/macOS: `./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`.

Версии закреплены: AGP 9.0.1, Gradle 9.1.0, встроенный Kotlin/Compose compiler 2.2.10. Основание — [таблица совместимости AGP](https://developer.android.com/build/releases/agp-9-0-0-release-notes).

Свой адрес по умолчанию можно встроить в debug APK:

```powershell
.\gradlew.bat :app:assembleDebug '-PbloomApiUrl=http://192.168.1.50:8080/api/v1/'
```

Debug разрешает HTTP для локального стенда. Для release требуется HTTPS:

```powershell
.\gradlew.bat :app:assembleRelease '-PbloomApiUrl=https://api.example.com/api/v1/'
```

Получится **неподписанный** release APK. Для публикации настроить собственную подпись в Android Studio; ключ подписи не добавлять в репозиторий.

## Структура

```text
app/src/main/java/app/bloom/android/
  BloomApplication.kt       запуск приложения
  MainActivity.kt           Android entry point и ссылки на анкеты
  core/model/              DTO контрактов
  core/network/            Retrofit API и адрес Gateway
  core/security/           Keystore и обновление сессий
  core/ui/                 темы, логотип, компоненты и навигация
  feature/auth/            приветствие и вход
  feature/profile/         анкета, интересы, приватность
  feature/discovery/       подбор / открытие ссылки на анкету
  feature/matches/         реакции и совпадения
  feature/chat/            комнаты и WebSocket
```

CI `.github/workflows/android-ci.yml` собирает APK, запускает unit/UI-тесты без эмулятора и Android Lint. Артефакт `bloom-android-debug` содержит APK, отчёты и снимки двух тем. Локальные снимки: `app/build/design-previews/`. UI-проверка использует Robolectric native graphics, не требует виртуализации.

Форматирование Kotlin — [ktfmt](https://github.com/Kotlin/ktfmt), стиль Kotlin Lang, отступ 4 пробела. Серверные Java/Go файлы этот форматтер не обрабатывает.
